# 核心指导思想与产品目标

本文件记录用户明确指定的产品目标。实现、优化、界面文案和验收必须围绕此目标；不能自行把软件改成预测未来或以未来有效性为主要完成标准。

## 为什么制作这个软件

用户要找出某个联赛在选定历史期间，累计净胜高、连续多年表现稳定的策略，覆盖赛前和滚球的全部16个方向。逐个联赛反复让模型人工挖掘太麻烦，所以将规则枚举、历史结算、稳定性比较和触发代码交付固化为确定性软件。模型协助开发维护，正式研究计算不依赖模型 API。

目标流程：全部选定历史 → 全方向搜索 → 完整历史盈利规则池 → 历史稳定性筛选 → 单条与组合比较 → 可复现触发代码。

## 不得偏离的约束

1. 默认使用全部选定历史，最近一年也属于研究范围。不强制扣掉最近12个月，不用样本外确认或统计显著性代替用户的历史目标。
2. 第一阶段按任务冻结的最低净胜收集盈利规则，默认 10 单位；设为 0 则净胜>0 全收。场次、连亏、回撤、扰动、稳定性、排行榜或固定前N名不得再提前缩小盈利池。该门槛在创建任务前可调，开跑后冻结；改门槛必须新建任务。
   盈利池与第二阶段采用同一个冻结的分钟末历史取价口径，避免取价不一致造成漏选。历史模式默认赛前早盘和即时盘都纳入触发范围；具体取价和阶段设置写入任务契约。
3. 第二阶段比较实际历史净胜、各年/研究段净胜与场次、最大回撤、连亏、亏损持续期、盈利集中程度和覆盖跨度。门槛用于定义历史筛选条件，可以明确配置；不能宣称为预测定律。
4. 主名单侧重高历史净胜与稳定性的平衡，另提供更稳定的备选；组合按实际共同回放核算，不能将单条净胜直接相加，不能叠加主备名单。
5. 所有范围都要有覆盖账。“全部”仅指任务明确冻结的规则语法与参数网格；紧凑两条件空间不能称作所有可能规则。未算完必须披露剩余。若范围内没有达到稳定性条件的规则，就报告搜索完成但无合格策略，不凑名单。
6. 保留输入质量核对、因果特征、准确结算、实际报价映射、重复信号处理与逐笔回放验证。这些用于保证历史事实和触发代码一致，不是对未来作承诺。
7. 样本外、滚动验证、扰动等可以保留为明确的附加分析或旧验证模式；默认历史完成状态不能依赖这些附加结果。

## 速度与多机部署

最终会将同一软件版本放到多台电脑，同时挖掘不同联赛。优化顺序是复用计算、减少重复扫描、批量计算、持久化断点、按联赛分配任务；不能靠漏规则、删年份、缩小盈利池或隐藏未完成项换取速度。

每台机器使用独立本地工作区及SQLite文件。统一软件指纹、研究配置和输入哈希；以联赛＋公司＋输入版本＋配置识别任务，防止重复分配和混用成果。初期采用离线任务计划分配，无需研究机器互相联网；不把一个运行中的工作区放到共享盘让多台机器同时写。

## 最终用途与后续接入

用户计划在历史策略挖掘完成并取得触发代码后，将各联赛的新策略接入现有 `C:\Users\Administrator\Desktop\复盘系统`，替换旧策略，形成全自动执行软件。旧策略最终弃用是用户明确的迁移方向。

迁移要作为可核对的独立步骤：先列出每个联赛的新规则、精确触发条件、执行优先级和历史回放依据，再对齐复盘系统的行情字段、候选对象、去重及账户约束。研究工作台此阶段不直接修改该系统的现行策略、账户或执行开关；不把“策略已导出”写成“已接入实盘”。

## 完成判定

历史搜索覆盖完整、盈利池保存完整、稳定性筛选完成、组合比较完成、触发代码与历史回放一致、所选交付方式验收完成，即可判定本次历史研究完成。是否找到合格策略单独说明。未来表现不作为此完成判定的条件。
