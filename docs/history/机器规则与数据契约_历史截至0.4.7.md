# 机器规则、事件与算法边界

## 原始输入

来源格式以用户《数据结构说明》为依据；并非通用博彩公司接口。表头包含sId、联赛、公司、盘口类型、状态、比赛分钟、当时比分、盘口数值、上水/大球、下水/小球、变化时间。读取UTF-8 BOM，剥`="..."`外壳不执行公式。源早/即为赛前，滚为滚球，不拿列表开球时间重新划阶段。sId字符串只在同一联赛公司研究内使用。

20列需要索引才能获得明确完赛状态；缺状态但有一致终场标签可继续**试算**，在data_audit标缺口，不能认证正式质量。23列的比赛状态可提供结果状态。冲突终值/状态或推迟中断被阻止进入结算样本；当时比分超过上传终场的行只标质量旗标，不擅改比分。无索引记录的质量库、行政改判和真实合约时期仍需外部核验。

输入文件按完整SHA-256去除同文件重复载入，不按报价行机械去重。同一市场同阶段同一分钟出现在两个来源文件时拒绝猜顺序；请提供不重叠的文件集。多联赛在排队时过滤不相关文件，每个原始文件若混合多个联赛仍按字段过滤。

## 标准事件语义 FSL_event_v1 ＋ v0.2严格项目契约

程序内事件包含provider、league、company、market_period、water_scale、line_scale、semantics；另包含：sid、mid（本次比赛索引）、eid（本次事件索引）、market(OU=0/AH=1)、phase(PRE=0/LIVE=1)、ts（UTC+08源墙钟分钟相对1970-01-01的整数）、source（文件哈希）、row（来源行号）、event_key（source:row）、minute、minute_raw、status、line、water[主/大,客/小]、score[当时主,当时客]、closed、valid。

`minute=-2`仅代表源文字中场；其他无法解析的分钟用MISSING，不能填0。本版不解析45+N/90+N为数字特征，但无分钟限制分支仍能处理有效报价。补时和目标时段语义未全覆盖，必须看报告。

盘口line单位=1/4球；water单位=1/water_scale；盈亏单位=1/(2*water_scale)。两位水位scale=100，如机器water=95表示0.95；line=1表示0.25球。源水位最多保留6位，超过时报错而非截断。缺失哨兵为−2^60。

未来标准事件可以通过 `lab.features.SignalEngine` 的feed接口进行确定性测试，但本包没有真实采集订阅服务。未来调用方必须统一字段、精度、序号、时间与合法市场；不能直接把任意API响应传进来。触发器拒绝final、全场比分、半场比分、比赛状态等事后字段；触发不要求比赛已结束。golden验收时的eligible只过滤统计范围，不进入触发特征。

## 历史特征与路径

状态键包含provider、league、company、market_period、water_scale、sid、market、phase。早/即共享赛前阶段历史；不同市场/阶段不混接。

- 阶段首价：第一条有效报价，含初次当前事件，差值0。
- 该盘口首次：该阶段这一有符号盘口首次有效出现，按实际主/客水位各自保留。
- 最近重返：从其他盘口重新进入当前盘口时新建基准；重开是否重置由keep/reset区分。
- 前一有效：keep可跨封盘保留；reset在无效/封盘事件清空。前一同盘水差仅在当前和前一有效盘口相同时有值。
- 历史极值：默认相对此前有效历史；初次事件无更早报价，本版以当前价初始化使差值0。`water_from_current_min`另外明确包含当前事件。
- 动态角色：当前L决定实际投注球队，历史水位使用这支实际球队的历史，不是把历史各时刻让方水位无声拼起来。后一种角色历史本版未实现。
- 投影事件：1升有符号盘、2降有符号盘、3同盘投注侧升水、4同盘降水；盘口变化优先。无变化不计步。
- path1/2/3为最近k个非零投影事件；state在后续无变化行仍为真，pulse只允许当前新增路径末步；span为这些步骤首尾的墙钟分钟差。普通事件最小幅度为源单位，特殊时限的独立最小步幅尚未实现。
- linepath2只看最近两次非零盘口变化，忽略所有水位变化。

本版同一事件key/位置内容完全相同的重复推送无信号；同key内容改变或旧位置迟到事件直接报错。它是故障关闭机制，不是已完成的真实行情更正系统。快照可以恢复特征和已触发集合，不等于真实订单崩溃事务已经验收。

## 规则树

根文件results/rules.json保存water_scale、规则列表、版本、两个false执行开关。每条包含id、direction、conditions、已算指标、priority、semantics、contract和content_hash；根另外含roster_hash与execution_policy。

conditions的feature必须在代码已支持字段内；op只能eq/le/ge/range；value和upper为上述单位的整数。range严格半开[value,upper)，条件之间AND。pulse/span仅可绑定path1/2/3。未知特征、未知比较符、版本错误不能静默忽略。中文描述由原子生成，不是另维护一份自由解释文本。

程序本身的内容哈希随每次运行冻结。数据、代码或字典变化不得复用旧断点。

## 报价压力与模拟

0=原触发价；1=原触发价减水0.05；2=目标墙钟分钟+1末尾可观察最新状态减水0.05；3=+2对应映射。来源无秒，不能解释成已经验证的真实60/120秒成交延迟。同盘且同阶段；AH执行比分基准改变则跳过，不拿新价配旧基准。报价最大陈旧度默认5分钟，仅为研究假设。换盘、封盘、未知比分或不满足水位均跳过，不退旧价。

订单按时间批次处理，同方向所有规则共享首单，整场累计本金最多配置值。同批同市场相反侧出现则拒绝该市场新单；同价同合约记录一次；旧版回归按规则ID字典序；standard按全池方向/逐笔签名冻结优先级，实际执行以rules.json的priority为准。没有真实订单写入或账户接口。

组合回撤先对同场订单求和再按比赛列表开球排序，只是比赛级代理曲线。资金到账、未结算风险、实际成交回执、第二筆资格及账户总风控均没有认证。


## 严格导入与状态恢复（当前口径）

SignalEngine默认必须从规则包取得完整contract，或由调用方显式传入经过核对的contract；无范围规则不会静默当通用规则运行。contract声明数据源、联赛、公司、市场期间、整数尺度和语义版本。原始来源API必须先经适配，不能用bind_event把其他联赛或不同单位强行改名。

未知事件字段会拒绝；score须双侧完整或同时缺失；valid须与盘口、水位和封盘状态一致。事件单位不匹配直接拒绝，不擅自做除100/除1000猜测。规则未知特征、未知比较符、未实现条件字段、非AND或非首次触发政策均不支持。规则内容哈希包括实际可执行条件及优先级；中文label不是执行依据。

当前快照schema为FSL_signal_state_v5。旧v3/v4快照缺少完整事件身份记录，不能自动恢复；需使用对应原版读取，或回补完整历史生成新快照。binding_hash绑定规则可执行内容、项目契约、执行政策及状态schema，payload_hash校验快照内容。两者不符拒绝恢复；不得复用旧fired集合。快照为深拷贝。SHA-256用于内容一致性，不是对来源真实性的数字签名认证。

同名规则阈值改变、名单变化、执行政策改变、不同联赛/公司、不同数值单位均不能沿用旧快照。旧38条先由显式迁移脚本转换并绑定原中超/皇冠契约，再做黄金回归，不改变原条件。

## v0.2有限搜索模块

L00基线；L01所有已登记单原子；L02本地核心双条件；L03本地核心三条件；L04已登记时限原子与一个/两个核心非路径上下文；L05新增细原子与一个/两个核心非路径上下文。普通state/pulse路径均进入核心；跨度原子不混进核心，作为L04锚点；L05锚点与核心及时限原子不重合。这是可直接seek的确定性表达清单，不是全部v3 W/C/T。

原子的integer comparator和条件交集先确定，再按场取首次。时限路径当前只支持普通投影事件的指定跨度，不支持另行最小步幅/可插入语义。窗口首价及跨市场等仍不支持，不能移植规则时静默忽略。

## v0.2组合选择

先全池检查已声明研究条件，再按方向和全局做固定多起点加入/移除/一换一替换。回撤约束覆盖原价和三个主要压力的组合比赛汇总曲线。默认研究预算10单位，低风险6单位，与单条≤5及单场投入4分开配置。

所有已比较动作有实际日志；未做动作不算失败，预算停止不算收敛。利润容差0.50在各起点锚定已经看过的最高可行净胜，不允许逐轮无限牺牲。利润落在容差内时优先较低回撤、较多共同覆盖、较简单条件。此为可复核局部方法，不能证明全局最优或统计独立。

所有订单账按规则ID字典序冻结优先级，多个起点不临时更改下单优先级。较低风险名单可能与默认名单不同，必须单独使用其规则及验收记录，不可叠加。


## v0.3新增有限语义

window_lo_hi_*为绑定的数字分钟半开窗口。当前实现九种窗口：0–16、16–31、31–46、46–61、61–76、76–91、0–46、46–91、0–91。窗口内第一条有效报价先于其他策略条件保存；无效/封盘不建立首价；建立后跨封盘保留。窗口之外全部差值为MISSING，文字中场不会当0分钟。盘口差用1/4球单位，水差用1/water_scale单位。

路径原子新增min_line_step及min_water_step正整数参数。1/2类步骤按各自有符号盘口变化的绝对幅度测试，3/4类按同盘口同侧水位绝对变化测试；必须每一步都满足相应下界。连续投影事件中不够幅度的步骤不会被跳过，而会使包含该步骤的原子不成立。一条同时变盘变水的报价仍仅投影为一个盘口事件，不凭空生造先后。span仍按所选首末事件墙钟分钟差，pulse只在末步新事件触发。该实现不是允许插入的子序列，也不代表所有标准T组合都已登记。

新增状态内容改变，v0.2快照不能直接载入v0.3。旧普通特征定义保持，原38条逐笔回归另行实际测试。


## v0.3.1 合并年数据与质量清单

平铺文件组简称只作导航，项目身份使用真实CSV联赛字段和公司字段。23列内的比赛状态/终场比分作为已合并索引标签，label_source=joined_index_columns；让球val、大小val不进入特征。没有外部独立核验时质量状态仍为UPLOADED_LABEL_UNVERIFIED。

同树质量交割清单与原始CSV一样写入输入清单、SHA-256与B包。source_hard_and_quarantine_v1按all、all_crown、csl_crown、pinbo/all_pinbo作用范围应用：硬问题及quarantine_rows_isolated对应比赛eligible=false，保留原始事件与quality_exclusions；remaining_suspicious及其他说明只写quality_notes，不修改投注权重。未识别的scope不跨公司套用。

workflow_status.json在A/B包内包含有限流程状态、筛选状态和待计算量。PARTIAL_RESULT不能解释成有限范围完整收口，PARTIAL_CORE继续表示完整v3尚有缺口。


## v0.4.3 当前口径补充

- 正式研究使用standard。旧smoke/routine/expanded仍保留旧字典和命名方向执行协议；0.4.4起直接筛选共用单项、联合、pulse/state、keep/reset扰动和固定“首次报价缺失”回退诊断。不能因没有数值邻域自动通过；失败或无样本均不能取得模拟资格。
- standard替代对照来自达到样本门槛的全部盈利家族代表（可含风险失败者）；旧规格对照只来自通过旧筛选的代表。本表先扫描可比池后定榜，每个已选策略最多输出四个最终对照，不重复输出中间榜单。默认样本比例带0.75—2倍，只限制描述性对照，不删第一阶段候选。
- 80/15指有合格赛果年份的原价有效首触发数量，含走盘，不含封盘/无效/无法结算及报价映射跳过。部分年度仍按15执行，不因月份少而删去该年度；数据截止日期与每年场次并列披露。压力情景的年度计数、保留率与质量旗标单列，年度15门槛不暗中扩展为压力情景门槛。
- 组合利润锚点取原价与三种压力情景的最小整数净收益；风险同时检查全部情景。比赛排序回撤仍为约束依据，新增比赛日聚合回撤作为辅助，不能用日内净额掩盖比赛级回撤。金额先用整数比较和相减，再除单位刻度展示。
- “去掉最盈利5笔”实际移除最多5笔正收益订单；少于5笔时会移除全部正收益订单。这是集中度诊断，不能把不足样本解释为充分验证。
- 赛前非零或不可解释比分保留证据并隔离比赛；空白赛前比分归零的数量有明确审计。日期、开球时间或赛果真实冲突仍阻塞，不取最早值/众数制造确定性。未知质量scope拒绝输入。
- engine_hash覆盖lab、web全部文件、app.py、运行依赖版本及哈希锁；tests与实际Python/平台/依赖版本另进入引擎验收绑定。release_hash覆盖白名单源码、UI、测试、文档与安装器。两种指纹不混称，历史证书只认证历史版本。
- 原始输入始终核对SHA-256；mtime/size只作变化检测，不能凭元数据相同跳过内容核验。快照内容校验不是外部来源认证，也不保证突然断电不丢最后一次写入；缺失文件立即报错，不用重试掩盖文件消失。
- .worker.lock的一字节是协作进程互斥标志，不是目录访问控制。缓存预算只约束各自缓存目标，不能冒充进程总内存上限。

金额阈值允许不落在收益刻度上的小数：先乘分母并向下取整，再与整数净值/回撤作严格大于或小于等于比较，两者与原十进制边界等价；超出整数范围直接报错，不使用MISSING充当阈值。
# 追加边界说明（0.4.3）

回补先验证历史及等待报价；若执行期间出现存储异常，当前执行器停止接受报价，关闭时不再写回已回滚的内存状态。必须重新打开原模拟账，按其最后持久化状态恢复；已持久化订单和回执不被伪装成整体回滚。

AH 强制登记绝对盘口 `[3,3.5)` 与 `>=3.5` 模板，包括零命中定义。模板增加会改变字典和搜索空间，旧任务不能跨引擎继续。

逐笔缓存默认限制为解码 JSON 字节合计 32 MiB、最多 128 项；这不是 Python 对象内存或进程 RSS 上限。等待历史队列按事件 ID 去重，冲突内容拒绝。合法但不适用的质量 scope 会保留审计计数。

滚动验证等待其他工作进程默认最多 30 秒，超时保存部分进度返回；已开始的训练仍受其任务预算控制，超时并不代表训练已完成。

0.4.4续跑和打包门禁使用包含前端内容的FSL_ENGINE_INPUTS_V3指纹。改变web内容会使旧任务拒绝续跑/打包。报表显示未分类结算数及分类状态；未分类结算阻止候选取得资格。去掉最盈利5笔仍按原始v3要求执行，同时报告实际移除笔数及不足5笔标记。B包排除worker日志和过期handoff日志，仅保留本次验收引用的日志并附排除清单。

字典准备进度以最多64个已完成特征或约2秒为批次保存，暂停和完成强制提交。异常退出可能重做尚未提交的一小批特征，原子登记幂等，不跳过未保存的规则定义；不再对每个无样本窗口重写全量游标。

0.4.5事件身份：同一契约和比赛内的所有市场/阶段共用event_key→完整事件内容SHA-256登记。相邻和非相邻的完全相同重放均在特征、报价及订单状态更新前忽略；同ID改变时间、行号、市场、阶段、价格或其他字段均拒绝。封盘及无效报价同样登记。每场最多100000个不同ID，达到上限拒绝新事件，不淘汰旧ID；正常close_match释放登记，封场墓碑继续阻止迟到重放。该限制是条目数上限，不是进程内存上限。回补与等待队列的同ID内容也必须一致。旧v4执行状态需由对应旧版读取或在新模拟账中完整回补，不能把旧fired集合直接迁入v5。
