# 0.7.0 使用与验收入口

本版保留单联赛、单公司、全部选定历史、香港盘净水及每笔1单位。
第一阶段只按冻结最低净胜收集盈利表达，不以稳定性或前N名提前删池。
第二阶段及组合实际唯一订单共同检查冻结的分段政策。真实下单、第二笔关闭。

默认紧凑语法 compact_v1；balanced_v1 增加必要水差、三条件核心、
1至3步路径及上下文，但不包含完整时限路径。v3_full 独立登记完整范围。
各规格是否完成看本任务覆盖账；未包含模块为 NOT_APPLICABLE，不算已搜索。
互补逐对研究是可选的独立观察结果，不改变主名单，不是执行批准。

新增默认政策：固定日历年；小段已发生亏损阻止进入稳定主名单；
小段正收益但样本少仍提示不足；完场状态缺失默认隔离。
可在建任务前明确选择固定365天锚点、标签试算或文件级完场契约。
这些条件开跑后冻结，旧任务不得强改哈希混用新政策。

历史拒单v2是后续1分钟同市场明确封盘且比分变化的代理假设，不是实际回执。
主备名单只可分别使用；更高收益回撤比不自动代表全部风险指标更低。
研究段不冒充真实赛季，未完整年份不当作完整三年。

当前软件验收入口：
`validation/_rationality_finish_20260916_r1/LATEST.json`
它指向本轮唯一目录的 `finish_result.json`。
只有状态为 PASS_SCOPED_070 且研究、执行和发布指纹都与源码一致，
才表示列明的软件范围通过。RUNNING、FAILED、PARTIAL 都不是发布通过。
以前0.6.3的测试数字、日期目录与Git标签只认证各自代码。

复验命令（项目根目录，已有锁定环境）：
```powershell
.\.venv\Scripts\python.exe -B validation/_rationality_finish_20260916_r1/run_acceptance.py
```

成功时提供同版 verified_source.zip、检查报告与证据汇总包。
全部整链为合成数据，full仅认证紧凑语法；受限用例通过表示正确保持PARTIAL。
不自动运行真实联赛，不认证完整v3穷尽、干净机器安装、在线漏洞扫描、
完整浏览器视觉验收或复盘系统接入，不保证未来盈利。
