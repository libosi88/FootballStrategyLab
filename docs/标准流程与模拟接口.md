# 历史研究流程与触发接口（0.7.0）

默认目标已改为 [核心指导思想与产品目标](核心指导思想与产品目标.md) 定义的全历史稳定高净胜研究。详细使用与多机步骤见 README 和 [多机挖掘与复盘系统接入](多机挖掘与复盘系统接入.md)。

S0：核对输入、使用全部选定历史并分配研究段（历史模式默认固定日历年，可在建任务前改为固定365天冻结锚点；旧的最后比赛日锚点保留给验证模式），并按完场证据政策分层：有终场比分但缺完场状态的比赛默认隔离并计数，可显式改为仅标签试算或声明文件级完场契约。不强制留出最近一年。

S1—S3：冻结16方向规则空间、搜索并保存净胜高于本次门槛的表达（历史默认10单位，0表示净胜>0全收）。搜索语法在开始前冻结为紧凑 compact_v1、中等 balanced_v1（核心三条件加补充路径上下文，不含时限路径）或 v3_full。预算与证明分开记账，不以稳定性提前缩小盈利池。

S4：以分钟末历史报价并剔除进球前 1 分钟内同市场明确封盘且比分改变的不可成交报价为历史净胜口径，按历史覆盖年数、各主要段净胜、场次、收益回撤比和集中度筛选；小段已发生亏损默认阻止该规则进入稳定主名单，成交少于5场的研究段只记证据不足，正收益也不算已证明稳定；连亏、各年收益和回撤完整披露。历史模式的附加扰动与全池风险比较默认关闭；开启时只作对照。

S5：按历史原价净胜与回撤比较加入/移除/替换，生成主名单与较稳定备选，分别使用。组合按实际派单再核一次分段稳定性、场次与历史跨度，并输出主备实际风险比较；开启互补研究时逐对结果单独保存，不改主名单。

S6：逐报价触发、持久化/流式模拟、五个报价情景订单重算核对，并与批量研究首触发参考逐条比对。压力情景的表现不作为历史资格条件，但计算及回放必须一致。

S7：生成历史最终决定、缺口说明、联赛接入清单和可选A/B交接包。无合格名单可作为完成搜索的真实结果；未来表现不是历史完成条件。

以下样本外/滚动命令作为独立分析保留，不是默认历史流程的门禁。`research_objective=validation` 为显式旧验证模式，保持旧政策供回归或附加分析。

## 命令

在项目目录执行（Windows可使用 `.venv\Scripts\python.exe` 代替 `python`）：

```text
python -B app.py run 数据目录 --league 中超 --profile standard
python -B app.py verify workspace/任务ID
python -B app.py export-candidates workspace/任务ID --output 全部原始盈利表达.jsonl.gz
python -B app.py evaluate-frozen --rules workspace/任务ID/results/rules.json 指定评测数据 --output 独立评测版本目录
python -B app.py walk-forward --job 任务ID --cutoff 2024-12-31 --test-end 2025-12-31
```

滚动诊断对每个截点重新发现、筛选并冻结名单后才读测试数据。同一场所有报价同组，训练水位精度和域只来自训练行，研究段以本折最后训练比赛为锚；训练折不再二次留出样本外。滚动诊断在原任务使用的历史范围内切折：历史模式为全部选定历史；验证模式的 labels.json 不含留出的最近12个月，留出期保留给一次性样本外评测。训练任务在有限预算下完成S0—S7后，其冻结名单照常评测，折状态标 `EVALUATED_PARTIAL_TRAINING_SEARCH`，滚动总体保持 PARTIAL；训练任务尚未产出名单时标 `PARTIAL_TRAINING`。`--wait-seconds 0` 表示等到该折训练结束。历史滚动与验证模式的样本外留出都是附加的历史检验，不是历史研究的完成条件，也不能改称未来实盘证据。

全量候选较大时默认以SQLite家族账、原子字典和可逆展开程序保存，不塞进一张CSV。`全部候选家族审查.csv`包括共享基础指标的家族，`全部候选审查.csv`是实际做了条件规范化与直接复核的规则；后者不能独自代表第一阶段全部原始表达。`方向汇总.csv` 列出各方向可用场次与所需场次。`数据证据分层.json` 记录完场证据分层；`组合分段稳定性.json` 记录组合实际派单后的分段证据，参与历史组合可行性判定；`主备实际风险比较.json` 与可选的 `互补研究摘要.json` 只作披露与独立观察。`league_registry.json`登记所有联赛任务，失败和部分结果也保留，不汇总不同联赛利润。

## 标准JSON模拟输入

启动：

```text
python -B app.py paper-stream --rules results/rules.json --state paper.sqlite3 --input quotes.jsonl --output decisions.jsonl
```

每行一个对象。原始报价完整字段见 `results/event.schema.json`，必须符合包内契约的联赛、公司、精度、语义版本；`market=0`大小球、`market=1`让球，`phase=0`赛前、`phase=1`滚球，`status` 为早/即/滚（历史模式默认早盘与即时盘都会触发；验证模式或设置 `prematch_trigger_status=即` 时只有“即”触发）。盘口整数除以4，水位整数除以water_scale。`ts`是1970-01-01起的墙钟分钟，源数据时区必须保持同一口径；整数缺失哨兵见features.json。终场结果、半场终值、收益或未知字段会拒绝。

| 消息 | 准确字段与含义 |
| --- | --- |
| 从开场完整订阅声明 | `{"type":"match_start","sid":"比赛ID"}`，仅在确实没有遗漏历史时发送；该场已有等待历史的报价时会被拒绝，须改用 history 回补 |
| 行情 | `{"type":"quote","event":{完整报价对象}}`，也可直接发送完整报价对象 |
| 历史回补 | `{"type":"history","events":[完整历史报价对象]}`，先校验后按同场时间回放；消耗历史首信号，不倒填订单 |
| 完整分钟水位线 | `{"type":"watermark","before":整数墙钟分钟,"sid":"比赛ID"}`，提交严格早于before的完整批次；sid可省略 |
| 比赛结束 | `{"type":"match_end","sid":"比赛ID"}`，封存该场特征；迟到事件不得重新开场 |
| 模拟回执 | `{"type":"receipt","intent_id":"ID","receipt_id":"唯一ID","status":"PARTIAL","filled_units":"0.4","confirmed":false}` |

单条消息无法解析、字段不合法、迟到、属于已封存比赛、等待历史队列已满或回执非法时，该行输出 `{"status":"MESSAGE_REJECTED","line":行号,"error":原因}` 并写入模拟账 alarms，后续消息继续处理；只有模拟账持久化失败才停止进程（重新打开同一state按最后持久化状态恢复）。进程结束时在标准错误输出拒绝条数。`--checkpoint-every N` 默认1；大于1可减少写盘，但崩溃后必须重发最后检查点之后的报价（批次提交幂等，不会重复下单）。

没有可靠历史时缓存等待，不把刚接入的价格当初盘。`--archive-history`只能用于已按整场完整历史排序的离线回放，不能用于刚接入的实时流。`--auto-fill`是假定模拟成交，默认为关闭。实时流EOF只保存状态，不凭空确认批次已经完整。水位线不能早于尚未完成的同分钟数据；停机后过期未提交批次会报警。实时match_end会记录并丢弃未提交批次及缺历史队列，再封存比赛，不倒填已经结束比赛的订单；离线完整档案回放才允许在末尾flush。

回执状态：`SUBMITTED_UNKNOWN`、`PARTIAL`、`FILLED`、`CANCELLED`、`REJECTED`、`SETTLED`。累计成交量不可倒退，确认取消/拒绝/结算必须 `confirmed=true`。未知及部分成交继续占用未确认风险；部分成交后的确认取消只释放未成交部分。订单、回执和整批提交均幂等，相同ID不同内容拒绝。主/客分支映射到对应让/受/平手核心名额，不可绕过每方向首单与整场上限。首单成交后的非重复后续信号只写影子记录，第二笔关闭。进球前报价拒单情景只用于档案研究；实时是否被拒以实际回执为准。

模拟器无网络账户适配器。接入真实行情及统一账户风控需要独立部署；各联赛研究的4单位上限不是每个联赛可重复使用的账户额度。当前交付是确定性触发与自动模拟，不授予真实资金执行资格。


## 操作与验收补充

- 新建页面默认紧凑语法（可选中等网格 balanced_v1 或 v3 完整语法）、计算预算全部为 0（不限）、组合改动与组合评价预算 0（直到局部最优）；0.5 保存的旧预算与 0.6.0 保存的组合改动/评价上限不会带入新任务，任何非零预算都会在“开始”按钮上方提示。设置自动保存到本机工作区（验证模式的标准门槛不可改），看到“设置已保存”后再刷新。修改目录必须重新扫描；同一未完成研究的重复提交会返回已有任务。
- 任务卡片显示冻结语法覆盖比例与历史研究结论（验证模式另显示样本外结论与推荐）；未算完的结果明确标为部分结果。
- 新建页面另有“历史稳定性、数据证据与互补研究”设置面板：研究段划分与固定锚点、主要段可用比赛占比、小段亏损政策、小段证据最少场次、最好段盈利占比上限、组合分段门禁、完场状态缺失政策与文件级完场契约来源、互补研究及其逐对预算。选择仅标签试算、允许小段亏损或关闭组合分段门禁时页面明确提示，结论必须保留该限定；第一阶段盈利池不受这些稳定性条件裁剪，条件在任务创建前冻结、开跑后不改。
- “同时计算的联赛任务数”是工作区设置（1—8），不进入研究配置；并行任务各自占用内存与磁盘。
- `max_run_minutes` 是每次启动/续跑的时长软预算；`max_output_mb` 是该任务总输出软预算。0表示不限制。在协作检查点检测，长步骤可能略超过预算，到限保存并暂停；不会冒充搜索完成或降低利润、场次和风险门槛。续跑重新计时，累计搜索节点不清零。内存设置是缓存目标，不是整个Python进程的硬上限。
- S7子进程和压缩循环可响应暂停，临时解压验收使用任务所在盘。空目录验收不按固定30分钟判定超时：引擎自检或逐条回放只要持续有输出就不会被终止，长时间无任何输出才判为挂起。B包打包前按压缩前体积预检磁盘，不足时暂停而不是在最后一步失败。暂停发生在发布前时不产生完成证书；恢复会重新验证打包。
- standard 的筛选与 orders_s0—s4 使用完整分钟末最新可执行报价，另保留触发瞬间 research metrics。流式模拟使用最新已观察报价，后续封盘、盘口或比分基准改变会拒绝；实时执行时间来自watermark或当前报价时间，不倒填成首信号时间。
- 新交接必须验证实际 `StreamingPaperRunner.feed → flush → 账本 → 重启`，四种原价/减水/延迟情景分别对照独立分钟末报价索引；拒单情景 s4 由档案报价索引重算订单（与筛选共用同一派单代码，不是独立实现），必须写出 `orders_s4.jsonl.gz` 与 `minute_close_orders_s4.jsonl.gz`，并在持久化模拟账上按拒单规则重放一次。`trigger_verification.json` 的 `streaming_paper_execution.scenarios` 含 s0–s3 流式结果和档案计价的 s4；`minute_close_orders_s0`—`s4.jsonl.gz`记录对照订单，仍不是外部成交证明。流式协调器不回放拒单情景。组合经济门禁按这五个已计价情景核对，标准冻结包缺少 `pregoal_rejection` 或缺少 s4 交接文件不能通过。
- 启动器核对服务的版本、代码指纹和工作区：同一工作区已有其他版本的工作台时提示先关闭它，不启动第二个服务；默认端口被其他程序占用时改用空闲本机端口；从不擅自停止别的程序。代码更新后，冻结于旧引擎的排队任务不会启动，而是暂停并提示用 `rebuild-stale` 重建。清理缓存或 CLI/滚动训练占用计算槽时，调度器启动的计算进程以代码75退出；进程以0退出但任务仍在排队（尚未领取）时也保持排队，稍后自动再试。只有领取前异常退出才标 ERROR。
- 调度器在界面服务进程内：关闭界面服务后，正在计算的任务继续，排队任务要等重新打开工作台才开始（关闭前界面会提示）。页面“全部续跑”或 `python -B app.py resume-jobs` 把当前版本的暂停或中断任务重新排队。磁盘剩余不足时新任务保持排队，不会逐个启动后暂停。
- 检查数据会跳过以“_”开头的文件夹（如 `_build` 备份）；文件格式不符时检查停止并指出该文件；同一联赛在多个目录有重复比赛时拒绝建任务并列出目录，请只选择其中一个数据目录。
