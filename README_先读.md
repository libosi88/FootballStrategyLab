**目的：把某个联赛全部选定历史中的盈利规则先收集完整，再找出连续多年稳定、累计净胜高的策略及组合。** 多个联赛无需逐一交给模型挖掘；研究计算由本地确定性程序执行，不调用模型 API。

最重要的产品依据是 [核心指导思想与产品目标](docs/核心指导思想与产品目标.md)。开发、优化与验收不得自行改成预测未来。

## 默认流程

选一个联赛和一家公司 → 使用全部选定历史 → 搜索全部16方向 → 保存净胜高于本次门槛的盈利规则池（默认10单位，可调） → 按历史跨度、各段净胜、场次、回撤和集中度筛选（连亏只披露） → 比较组合 → 核对触发 → 导出结论及A/B包。

- 最近一年也用于历史研究，不强制留出。样本外确认与显著性不是历史完成条件。
- 历史模式默认赛前早盘和即时盘均可触发；盈利池与第二阶段统一按冻结的分钟末取价口径计算，并剔除进球前 1 分钟内同市场明确封盘且比分改变、实际无法成交的报价（代理假设 v2，不是真实回执；空白滚球比分不算进球证据；首次信号记零，不顺延补单）。
- 第一阶段不以场次、回撤、稳定性或排行榜提前缩小盈利池。盈利池最低净胜默认10单位，可在创建任务前改，0表示净胜>0全收；开跑后冻结。
- 历史筛选默认至少覆盖2年（365天/年）、主要研究段净胜为正，场次要求随方向可用比赛数变化（40—80场），历史收益回撤比至少2。研究段默认按固定日历年（可改为固定365天冻结锚点）；占比不足的小段只要已发生亏损就不进入稳定主名单，成交少于5场的段只记证据不足；有终场比分但缺完场状态的比赛默认隔离，可显式改为仅标签试算或声明文件级完场契约。稳定性门槛与这些政策都可在创建任务前明确调整，开跑后冻结。
- 默认组合按实际历史分钟末报价净胜与回撤比较；较稳定备选的收益回撤比要求为3。主备分别使用，不叠加。组合搜索不设改动与评价次数上限，直到局部最优；按场增量重放，结果与逐单完整回放相同。组合按实际派单再核分段稳定性、场次与历史跨度，并输出主备实际风险比较：更高的收益回撤比不自动代表全部风险指标更低。
- 压力情景保留作附加对照与订单核对。历史模式默认关闭逐规则额外扰动和全池两两风险对照，以减少重复计算；开启附加对照也不因此删掉历史盈利池。
- 数据质量、因果特征、正确结算、输入哈希和触发一致性检查保留。

“完整”指本任务冻结的语法与参数网格。默认紧凑语法包含基线、单条件和两条件组合；可选的中等网格 `balanced_v1` 把核心条件扩到三条件并补充1至3步路径及上下文（不含时限路径）；可选的 `v3_full` 范围大得多，可能长期算不完。不能将两条件结果称为所有可能规则，也不承诺组合搜索达到数学全局最优。达到预算仍会明确保留未评价数量。

旧的 `research_objective=validation` 模式作为附加验证保留，沿用净胜>10、最近12个月留出以及旧的最后比赛日研究段锚点、小段亏损只披露、缺完场状态仅标签试算等政策；不是新任务的默认目标。

## 启动与使用

双击 `启动工作台.bat`。首次设置选用64位 Python 3.11—3.13、创建本地环境并安装锁定依赖；不使用系统默认 Python 3.14。已有环境直接打开本机网页。下文命令行示例都在项目目录运行，Windows 请用 `.venv\Scripts\python.exe` 代替 `python`；系统或其他 Python 通常没有安装锁定依赖，会在导入时报错。

默认端口被其他程序占用时，自动选择空闲端口。**请使用终端打印的 `http://127.0.0.1:端口`，不要用 `localhost`**：本机 8765 端口上另有一个无关程序在 IPv6（`::`）上监听，`localhost` 可能被解析到它、显示成别的目录列表，而工作台端不会有任何提示——两者可以同时存在，因为那个监听是仅 IPv6 的。下次启动先核对软件与工作区身份后复用，不停止其他程序。同一工作区已有另一版本的工作台在运行时，启动脚本提示先关闭它。旧版本冻结任务不会自动开始。迁移前用 `python -B app.py rebuild-stale --job 原任务ID --profile standard --dry-run` 核对输入、模式、预算及参数差异；省略 --dry-run 才创建新任务，追加 --queue 才排队。默认保留旧验证模式；全历史迁移请显式使用 `--config config/rebuild_historical.json`。失败返回非零退出码，原任务和断点保留。详见 docs/版本与维护说明.md。

1. 选择 CSV、目录或ZIP，点击“检查数据”。支持平铺年度文件及20列/23列格式。以“_”开头的文件夹（如 `_build` 备份）会被跳过；同一联赛在多个目录有重复比赛时不能建任务，请只选择其中一个目录。**请按国家目录或联赛目录选择，不要直接选中整棵数据树**：2026-09-16 实测，数据树下 `挖掘注意` 一类辅助目录含有“像完整指数但缺必要列”的 CSV，会让整次检查报错中止；`皇冠开盘至少200场` 这类旧平铺副本与按国家目录的内容重复，一并选中会因重复比赛被拒绝建任务。单个联赛目录（如中超 679 场、约 120 MB）检查约需半分钟，质量交割清单会被自动找到。
2. 按实际CSV中的联赛和公司单选任务；不同联赛不会混算。
3. 保持“全历史稳定高净胜”目标，选择明确的语法和预算、历史筛选条件。
4. 点击开始。原始数据只读，任务与断点写入独立工作区。
5. 看 `最终决定.md`、各年/研究段指标、搜索覆盖账和历史名单。若没有符合条件的策略，报告无合格策略，不凑名单。
6. 暂停或中断的任务可在页面点“全部续跑”。关闭界面服务不停止正在计算的任务，但排队任务要等重新打开工作台才开始。

单个联赛任务目录可达数 GB（盈利池档案、搜索账与组合审计日志），请预留磁盘；任务完成后可用 `python -B app.py cleanup-workspace --apply` 释放已完成方向的可重建缓存。**要把整棵数据树跑完是 TB 级的磁盘需求**：数据树里约有 2,300 个「联赛×公司」组合，其中约 1,100 个能达到默认场次与历史跨度门槛；已有真实样本为单任务 2.5 GB（跑到组合比较阶段）到 4.4 GB（只跑 1 个方向、有节点预算），而默认是 16 个方向、历史模式不设节点上限。可回收的只有 `masks.sqlite3`、`virtual_columns`、`review_columns` 三类可重建缓存，`arrays.npz`、`atoms.sqlite3`、`search.sqlite3` 等证据不释放。因此实际可行的方式是「跑一个联赛 → 归档搬走 → 再跑下一个」，不要期望所有联赛的产物同时留在本机磁盘上。

大型JSON/Markdown最多预览前1 MiB并明确提示截断，完整下载保留全部内容。切换预览会取消旧请求。

## 完成状态

- `HISTORICAL_RESEARCH_COMPLETE`：冻结范围搜索、盈利池审查、历史组合比较、触发核对与交接验收完成。名单是否为空另行说明。
- `HISTORICAL_RESEARCH_COMPLETE_NO_HANDOFF`：上述历史研究完成，按配置不生成A/B包。
- `PARTIAL_RESULT`：还有搜索、筛选或交接缺口；看具体剩余，不冒充完整结果。

历史完成状态不包含未来判断。策略对指定历史表现如何，以逐笔证据和统计为准。

## 速度与多台电脑

同版程序可以在多台电脑上按联赛分工，使用独立本地工作区。保留批量计算、因果扫描复用、家族/掩码缓存和断点；不靠删年份、漏规则或隐藏未完成项加速。

```text
python -B app.py fleet-plan D:\足球数据 --nodes 8 --company 皇冠 --output D:\本轮分配
python -B app.py fleet-import D:\本轮分配\node_001.json --data-root E:\足球数据 --queue
```

计划按报价行数平衡，各联赛不重复分配；每个节点计划的 `required_files` 列出该机需要复制的文件。导入校验软件版本和输入哈希，重复导入不会重复建任务；不共用运行中的SQLite文件。详见 [多机挖掘与复盘系统接入](docs/多机挖掘与复盘系统接入.md)。

## 触发交付与后续接入

A包提供名单、精确条件、事件契约、Python触发引擎、历史黄金信号和回放工具；B包保存完整审计与复跑资料。每套名单附 `integration_manifest.json`，记录联赛身份、规则绑定和触发入口。

用户计划将各联赛的新策略接入 `C:\Users\Administrator\Desktop\复盘系统`，最终弃用旧策略。该系统的Node.js策略注册、行情转换、候选去重和执行约束需要单独对齐。本版没有修改其旧策略或账户配置，也没有将Python包直接当作原生JS插件。
